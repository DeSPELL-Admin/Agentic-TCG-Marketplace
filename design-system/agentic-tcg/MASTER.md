# Agentic TCG — 랜딩과 카드 검색

상태: 실행 Web에 적용. [Web README](../../apps/web/README.md)에 실행·SSR·검증 범위를 정리합니다. [이전 코랄 플레이룸](../../docs/design/archive/coral-playroom.html)은 보관용이며 현재 디자인 기준이 아닙니다.

## 적용한 스킬과 우선순위

`ui-ux-pro-max`의 `collectibles marketplace editorial minimal --design-system`, `E-commerce Marketplace --domain product`를 조회하고 `frontend-design`의 실제 콘텐츠 중심·불필요한 눈썹 타이틀 제거 원칙을 적용했습니다.

자동 생성된 디자인 시스템은 보라 배경·후기·홍보 섹션을 제안해 이번 요청과 맞지 않았습니다. 범위를 좁혀 E-commerce 분류를 확인했으며 상품 중심 탐색과 명확한 이동 경로만 참고합니다. **사용자가 지정한 순백 배경이 우선**입니다. 후기·인기 순위·실적을 만들지 않습니다.

## 제품 목적

한국어 이름으로 카드를 찾고, 실제 카드와 원본 참고 시세를 비교하는 화면입니다. 컬렉션을 탐색하는 시선은 아트워크에, 판단에 필요한 정보는 가격·통화·근거에 둡니다. 코랄은 조작에만 제한적으로 사용합니다.

데이터는 카드 171종, 한국어 이름 136종, 이미지 URL 166개, 참고 시세 1,145개입니다. 별도의 합성 카드 3종과 가격은 데모로 구분합니다. 한국어 표시 이름을 한국어 인쇄 카드로 오인하게 만들지 않습니다.

## 페이지 구조

### 랜딩 `/`

```text
브랜드                                                   홈 / 카드 검색

포켓몬 카드                    카드 정보와 해외 참고 시세를 확인하세요.
                               [카드 검색]

리자몽 카드 이미지             피카츄 카드 이미지           이브이 카드 이미지
이름 / 세트·번호               이름 / 세트·번호             이름 / 세트·번호

브랜드                                                   데이터 안내 펼치기
```

화면을 기억하게 하는 요소는 실제 카드 세 장입니다. 과장된 슬로건·눈썹 타이틀·장식용 번호·화살표·배지·겹친 패널·자동 움직임을 넣지 않습니다. 리자몽·피카츄·이브이 이름 검색 결과 중 이미지가 있는 카드 한 장씩을 사용하며 인기·추천 순위가 아닙니다. 조회 실패 시 성공한 카드만 표시하고 검색 진입은 유지합니다. 가격 API를 호출하지 않습니다.

### 카드 검색 `/cards`

`카드 검색` 제목 → 이름 입력 → 검색 결과로 이어집니다. 랜딩 이미지나 소개 문구를 반복하지 않습니다. 검색어는 `/cards?q=검색어`, 상세와 복귀 링크에 보존합니다. 기존 `/?q=검색어` 주소는 새 검색 주소로 리다이렉트합니다. 초기화·없는 카드·오류 화면의 목록 복귀도 `/cards`를 사용합니다. 작은 결과 수는 빈 컬러 패널을 만들지 않고 같은 갤러리 규칙으로 진열합니다.

현재 API는 q/limit와 nextCursor:null을 제공합니다. 조회된 최대 20종 안에서 이미지 있는 카드를 먼저 보여줍니다. 세트 필터·전체 개수·페이지 이동은 backend 계약 확장 후 연결합니다. 받은 일부 데이터만 필터링하고 전체 검색처럼 표시하지 않습니다.

### 카드 상세

```text
검색으로 돌아가기 / 세트
────────────────────────────────────────────────────
큰 카드 이미지       한국어명 / 원문명
                    대표 가격·원본 통화
                    제공자·변형·검증 상태·갱신 시각
                    인쇄 언어 / 번호 / 에디션 / 보존 상태
────────────────────────────────────────────────────
참고 시세 | 평가 근거 | 카드 정보       실제 섹션으로 이동
해외 참고 가격 목록과 각 출처
USDC 평가와 근거 [펼치기]
한국어 표기 안내 / 내부 식별 정보 [펼치기]
```

첫 화면에서 가격을 확인하고 아래에서 근거를 비교합니다. 가격이 없는 것을 실패와 혼동하지 않습니다. 추정 적정가가 있으면 USDC를, 그렇지 않고 참고 시세가 있으면 원본 EUR/USD를 대표값으로 표시하며 미검증·원본 참고용이라는 설명을 함께 둡니다. 가격 패널을 겹쳐 같은 금액을 반복하지 않습니다.

## 색과 타이포그래피

| 역할 | 값 | 규칙 |
| --- | --- | --- |
| 페이지·헤더·이미지 영역·정보 면 | `#FFFFFF` | 전체 배경은 순백 |
| 본문·제목 | `#24212D` | 아트워크와 가격을 읽는 기준 |
| 보조 정보 | `#6B6574` | 세트·시간·설명 |
| 브랜드 코랄 | `#C94F57` | 작은 표식·구분 강조 |
| 주요 버튼 | `#B6404B` | 흰 글자 대비 5.49:1 |
| 링크 | `#8B303E` | 밑줄/명확한 조작 형태 병행 |
| 구분선 | `#E5E2E8` | 얇은 구역 구분, 입력 경계의 대체 아님 |
| 입력 경계 | `#897F97` | 입력과 흰 바탕 구분 |

페이지 전체를 밝은 회색·보라·분홍으로 채우지 않습니다. 성공·오류·데모의 작은 의미별 라벨에는 지정 상태 토큰을 사용할 수 있지만 색만으로 상태를 전달하지 않습니다. 정상 작동하는 버튼이 코랄이라는 이유로 오류 상태를 뜻하지 않습니다.

- 글꼴은 저장소의 Pretendard Variable v1.3.9, 폰트 CDN 없음.
- 랜딩 제목 38~64px / 650, 검색 제목 28~36px / 650, 결과 제목 16px / 600, 카드명 16~20px, 본문 16px, 설명 13~15px, 보조 메타데이터 12px.
- 제목은 폭을 제한하고 `text-wrap: balance`를 보조적으로 적용합니다. 특정 단어만 꾸미거나 강제 줄바꿈으로 화면별 문장을 맞추지 않습니다.
- 가격은 tabular-nums로 표시하고 원본 숫자의 정밀도·통화를 보존합니다. 반복 배지 대신 간결한 라벨과 상세 근거를 사용합니다.

## 반응형과 상태

- 최대 컨테이너 1320px, 데스크톱 좌우 40px, 모바일 20px.
- 목록 4열 → 1100px 미만 3열 → 640px 미만 2열 → 매우 좁은 화면 1열.
- 랜딩은 데스크톱에서 제목과 검색 진입을 좌우 배치하고 모바일에서 순서대로 배치합니다. 카드 세 장은 같은 기준선의 3열로 유지합니다. 검색은 별도 페이지입니다.
- 상세는 768px 미만에서 한 열로 바꾸고 원본 가격 표도 모바일 행 묶음으로 읽을 수 있게 합니다.
- 클릭 영역 44px 이상, 키보드 포커스 유지. 그림 설명은 색·hover에만 의존하지 않습니다.
- 카드 hover 이동·자동 애니메이션은 사용하지 않습니다. 링크는 밑줄·버튼 색 변화로 조작을 알립니다.
- 이미지 실패는 이름·세트가 있는 대체 화면으로 복구합니다. hydration 전에 실패한 요청도 확인합니다.
- 가격 API 일부 실패는 목록을 지우지 않습니다. 자료 부족과 조회 실패는 서로 다른 문구를 사용합니다.
- 카드 이름·세트·가격 종류·통화는 목록에서 바로 확인하고 상세에서 원문·판본·상태·근거를 확인합니다.

## Emotion과 데이터 경계

파일 상단에 import·타입, 그 다음 컴포넌트, **같은 파일 하단에 styled/css 선언**을 둡니다. 별도 styles 파일로 분리하지 않습니다. 팔레트는 `src/styles/theme.ts`에서 관리하고 스타일 전용 props는 DOM으로 넘기지 않습니다.

페이지와 API 조회는 Server Component 및 `server-only` 모듈에 유지합니다. 화면 컴포넌트는 DTO를 받아 표현하며 Core API URL이나 비밀값을 브라우저에서 읽지 않습니다. 요청별 Emotion cache와 `useServerInsertedHTML`로 전역/일반 규칙을 head에 주입합니다. 해당 앱·버전에서 SSR·클라이언트 이동·hydration을 검증하며 일반적인 라이브러리 전체 호환성을 보증하지 않습니다.

현재 화면 범위는 카드 탐색·상세입니다. Agent·매물·내 카드·거래 내역은 실제 담당 모듈의 API 연결 후 동일한 순백·정보 위계 기준으로 추가합니다.

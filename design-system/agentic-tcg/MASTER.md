# Agentic TCG 프론트엔드 디자인 설계 — 코랄 플레이룸

상태: 구현 전 설계안. 현재 Web은 기존 화면이며 Emotion 패키지와 아래 컴포넌트는 아직 적용하지 않았습니다. 검토용 시각 자료는 [HTML 미리보기](../../docs/design/frontend-preview.html)에 있습니다.

## 제품 방향

한국인 수집가가 카드를 찾고, 원본 가격의 성격을 이해하고, 추후 Agent에게 구매 조건을 맡기는 서비스입니다. **코랄 플레이룸**은 카드를 테이블 위에 펼치고 한 장을 집어보는 경험을 중심으로 합니다. 라벤더 플레이매트 위에 정렬된 카드, 남보라색 글자, 코랄 조작부로 수집의 활기를 표현합니다. 가격과 검증 근거는 흰색 정보 영역에 정리합니다.

상단 세트 탭과 넉넉한 3열 카드 진열로 구성합니다. 카드 타일의 아트워크와 정보는 한 장의 종이처럼 묶고, 선택한 카드에만 코랄 책갈피와 약한 들림을 적용합니다. 배경 그라데이션·무작위 회전·자동 홀로그램 효과·게임화된 가격 표시는 사용하지 않습니다. 개성은 카드를 펼치는 주 영역에 집중하고 나머지 화면은 읽기 쉽게 유지합니다.

현재 자산은 수집 카드 171종, 한국어 표시 이름 136개, 이미지 URL 166개, 참고 시세 1,145개입니다. 종명 사전 1,025쌍은 카드 수가 아닙니다. 트레이너·에너지·미대응 이름을 임의 번역하지 않습니다. 기존 합성 카드 3개와 가격은 별도 데모 데이터입니다.

`frontend-design`과 `ui-ux-pro-max`를 사용해 검토했습니다. 스킬의 제품 검색은 TCG 카탈로그에 맞는 결과를 찾지 못해 추천 팔레트·랜딩 구성을 채택하지 않았습니다. 접근성·서버/클라이언트 경계 원칙을 참고하고 아래 시각 체계는 프로젝트에 맞게 직접 설계했습니다.

## 화면과 정보 구조

| 영역 | 경로 제안 | 주요 내용 | 연결 상태 |
| --- | --- | --- | --- |
| 카드 탐색 | `/` | 검색, 카드 이미지, 표시 이름, 세트·번호·인쇄 언어, 가격 상태 | 기존 API로 우선 구현 |
| 카드 상세 | `/cards/[id]` | 확대 이미지, 속성, 추정 적정가, 원본 참고 시세·검증 근거 | 기존 API로 우선 구현 |
| 고정가 매물 | `/market` | 매물·가격·보존 상태·구매 조건 확인 | Trading API 연결 후 |
| 내 카드 | `/collection` | 보유 목록·등록 상태 | Inventory API 연결 후 |
| Agent | `/agents`, `/agents/[id]` | 실행·중지, 정책·예산, 로그·주문·결제 상태 | Agent/MCP/Payment 연결 후 |
| 거래 내역 | `/activity` | 진행·완료·실패 거래와 결제 상태 | 담당 API 연결 후 |

상단 탐색은 최종적으로 카드 탐색 / 마켓 / 내 카드 / Agent / 거래 내역입니다. 현재 구현에서는 연결된 화면만 활성 경로로 제공합니다. 미구현 메뉴와 버튼을 동작하는 것처럼 만들지 않습니다. 향후 영역을 미리 보여줘야 한다면 별도 연결 예정 안내로 구분합니다.

### 카드 탐색

```text
브랜드      카드 탐색   마켓   내 카드   Agent   거래 내역      데모 안내
──────────────────────────────────────────────────────────────────────
카드 탐색
[ 카드 이름 검색 ........................................ ] [검색]
적용 필터 / 조회 결과 수                           보기·정렬 도구
──────────────────────────────────────────────────────────────────────
세트 탭: 전체 / Base Set / Jungle             필터 열기(API 연결 후)
┌ 라벤더 플레이매트 ─────────────────────────────────────────────────┐
│        [실제 카드]        [실제 카드]        [실제 카드]            │
│        한국어명           한국어명           한국어명               │
│        세트·번호          세트·번호          세트·번호              │
│        인쇄 언어          인쇄 언어          인쇄 언어              │
│        가격 상태          가격 상태          가격 상태              │
└───────────────────────────────────────────────────────────────────┘
──────────────────────────────────────────────────────────────────────
조회 범위 안내 / 페이지 이동(API 확장 후)
```

- 첫 화면부터 카드와 검색창이 보이도록 합니다. 큰 홍보용 히어로·성과 숫자·캐러셀은 두지 않습니다.
- 왼쪽 고정 사이드바를 없애고 세트 탐색은 플레이매트 위의 수평 탭, 고급 조건은 필터 패널로 이동합니다. HTML 미리보기의 세트 탭은 예시 6종에만 적용되는 로컬 동작이며 실제 앱의 전체 카탈로그 필터를 구현한 것이 아닙니다.
- 한 카드는 이미지 → 한국어 표시 이름 → 원문명 → 세트·번호 → 인쇄 언어 → 가격 상태 순서입니다. 이름·핵심 메타데이터를 좌측 정렬하고 금액은 우측 정렬 가능한 독립 영역으로 둡니다.
- 카드 아트워크는 `object-fit: contain`으로 전체를 보여주고 폭:높이 약 63:88의 고정 슬롯을 예약합니다. 이미지 없는 카드에는 이름·세트 정보가 있는 차분한 대체 화면을 제공합니다. 이미지 실패 시 자동 대체하고 무한 재시도하지 않습니다.
- 현재 검색 API는 q·limit만 지원하고 nextCursor는 null입니다. 초기에는 검색만 연결하고 조회된 개수로 표시합니다. 전체 개수·세트/언어 필터·정렬·페이지 이동은 API 계약을 확장한 후 활성화합니다. 받은 20장만 필터링하고 전체 171종 검색인 것처럼 표시하지 않습니다.
- URL에 검색 조건을 유지하고 상세에서 돌아올 때 검색 상태와 스크롤을 복원합니다. 지원 후 사용할 필터는 세트·인쇄 언어·가격 자료 여부이며 q/set/language/cursor 계약은 별도 확정합니다.
- 외부 API가 반환한 에디션·보존 상태 UNSPECIFIED는 사용자에게 미확정으로 표시합니다. 상품 상태를 정상·미개봉·NM으로 추정하지 않습니다.

이미지는 좌측 약 40%, 정보는 우측 약 60%로 배치합니다. 거래 API 연결 후에만 구매·매물 패널을 추가합니다. 가격 이력 데이터와 의미가 확정되기 전에는 차트를 생성하지 않습니다. 현재 여러 시점의 스냅샷을 실제 체결 기록으로 표현하지 않습니다.

### Agent 작업대(후속 연결)

왼쪽은 Agent 목록, 중앙은 선택 Agent의 상태·정책·활동 기록, 오른쪽은 예산과 실행 제어를 배치합니다. 모바일에서는 상태·중지 제어 → 예산 → 정책 → 활동 기록 순서로 읽습니다. 실행 중에도 중지 제어를 쉽게 찾을 수 있게 하고 상태에 색·텍스트·아이콘을 함께 사용합니다. 예산과 거래 상태는 실제 API 응답으로만 표시합니다.

## 컬러 팔레트

라이트 테마를 먼저 완성합니다. 밝은 회색은 방의 바탕, 라벤더는 카드를 펼치는 플레이매트, 화이트는 카드 정보와 가격 근거를 읽는 면입니다. 코랄은 조작과 선택에 집중하고 남보라로 제목·본문·숫자를 묶습니다. 색이 카드의 희귀도나 가격 상승을 뜻하지 않습니다.

| 토큰 | 이름 | 값 | 사용 |
| --- | --- | --- | --- |
| color.bg.canvas | 페일 그레이 | `#F5F5F7` | 전체 배경 |
| color.bg.surface | 화이트 | `#FFFFFF` | 검색·상세·대화상자 |
| color.text.primary | 딥 플럼 | `#302C49` | 제목·본문·금액 |
| color.text.secondary | 더스티 플럼 | `#665F76` | 설명·메타데이터 |
| color.brand.primary | 플레이 코랄 | `#C94F57` | 브랜드 표식·선택 책갈피 |
| color.bg.playmat | 소프트 라벤더 | `#DCD6ED` | 카드 진열 영역·선택 배경 |

조작 토큰: `color.action.primary=#B6404B`, hover `#9F3440`, 링크 `#8B303E`, 포커스 `#51417C`, 코랄 subtle `#FBE8E9`, 구분선 `#DED9E5`, 입력 경계 `#897F97`. 약한 구분선은 장식용이며 입력 영역의 유일한 경계에는 사용하지 않습니다.

제안한 브랜드 코랄 `#C94F57`은 흰 글자 대비가 4.43:1이라 작은 버튼 글자에는 부족합니다. 브랜드 표식은 이 색을 유지하고 흰 글자의 주요 버튼에는 더 짙은 `#B6404B`를 사용해 5.49:1을 확보합니다. 라벤더 위의 작은 링크는 더 짙은 링크 토큰을 쓰고 밑줄을 함께 제공합니다.

| 의미 | 전경 / 배경 | 라벨 예 |
| --- | --- | --- |
| 확인·완료 | `#176B4A` / `#E6F4EB` | 검증 완료·거래 완료 |
| 주의·미확정 | `#875100` / `#FFF4CD` | 판본 확인 필요·자료 만료 |
| 오류·중지 | `#9F244A` / `#FFF0F3` | 실행 실패·결제 실패 |
| 합성 데이터 | `#545068` / `#ECEAF2` | 데모 가격 |

계산한 대비는 본문/전체 배경 12.19:1, 보조 글자/전체 배경 5.57:1, 흰 글자/주요 버튼 5.49:1, 딥 플럼/라벤더 9.41:1입니다. 코랄은 브랜드·행동 색이며 오류 여부를 뜻하지 않습니다. 실패는 오류 라벨·아이콘·문구로 구분하고, 데모 여부도 중립색 라벨로 명시합니다. 실제 hover·disabled·포커스·이미지 배경 조합은 구현 시 별도 검증합니다.

## 타이포그래피·간격·반응형

- 글꼴: [Pretendard Variable](https://github.com/orioncactus/pretendard) 중심, 한국어 시스템 글꼴 fallback. 구현 시 버전·라이선스 고지를 포함해 로컬 제공하고 외부 폰트 CDN에 의존하지 않습니다. HTML 미리보기는 시스템 폰트를 사용합니다.
- 본문 16px/1.6, 보조 14px/1.5, 카드명 18px/1.4, 섹션 제목 24px/1.35, 페이지 제목 32~36px/1.25. 제목은 750~800의 둥글고 단단한 획으로 활기를 더하고 과한 자간 축소는 피합니다. 작은 배지의 하한은 12px입니다.
- 제목 weight 700, 본문 400~500, 금액 600~700. 숫자는 `font-variant-numeric: tabular-nums`를 적용합니다. 한국어 문장은 keep-all을 기본으로 하고 긴 원문·URL·UUID는 overflow-wrap:anywhere로 처리합니다.
- 간격: 4 / 8 / 12 / 16 / 24 / 32 / 48 / 64px. 컨테이너 최대 1280px, 좌우 여백 모바일 16px·태블릿 24px·데스크톱 32px.
- 모서리: 배지 5px, 입력·버튼 10px, 카드 타일 14px, 플레이매트 24px, 정보 패널 12px. 타일은 실제 카드와 설명을 하나의 흰색 면으로 묶습니다. 얕은 바닥 그림자로 종이의 두께를 표현하고 선택 카드만 3px 들어 올립니다. 가격 패널과 표에는 같은 그림자를 반복하지 않습니다.
- 탐색 grid: 360px부터 2열, 640px부터 3열, 데스크톱도 여유 있는 3열입니다. 사이드바 대신 수평 탭과 접는 필터를 사용합니다. 좁은 화면이나 큰 글꼴 설정에서 최소 카드 폭을 확보하지 못하면 1열로 전환합니다.
- 상세: 960px 이하에서 이미지 → 속성·평가 → 참고 시세 순서의 단일 열. 작은 화면의 시세 표는 제공자별 행 묶음으로 바꾸고 페이지 전체의 가로 스크롤을 만들지 않습니다.
- 주요 조작 영역 최소 44×44px, 키보드 포커스 3px 포커스 토큰과 충분한 offset. hover에만 상세 정보를 숨기지 않습니다. 움직임은 필터 열림·선택·피드백에 120~180ms로 제한하고 reduced-motion을 존중합니다. 타일은 기본 상태에서 기울이지 않아 스캔과 키보드 이동의 질서를 유지합니다.

## 데이터 상태와 문구

| 상황 | 표시 원칙 |
| --- | --- |
| 한국어 종명 있음 | 한국어 우선, 원문명 보조. 인쇄 언어는 별도 표시 |
| 원본 EUR/USD 가격 | 해외 참고 시세, 통화 유지, 갱신 시각·출처 제공 |
| MOCK 평가 | 데모 가격 라벨. 실제 가격으로 읽히는 단독 금액 금지 |
| MARKET AVAILABLE | 추정 적정가(USDC), 사용 표본·낮은 신뢰·근거 표시 |
| INSUFFICIENT_DATA | 평가 자료 부족. 0 USDC·대시만으로 의미를 대체하지 않음 |
| 가격 API 실패 | 가격 정보를 불러오지 못함과 재시도. 자료 부족과 구분 |
| 판본 미검증 | 판본 확인 필요. 원본 시세를 자동 적정가로 승격하지 않음 |
| 검색 결과 없음 | 검색어를 유지하고 조건 초기화·다른 검색 안내 |
| 이미지 없음/실패 | 카드명·세트가 있는 대체 이미지 영역 |

전역에 필요한 데모 안내는 짧게 한 번 표시하고, 데이터 성격은 가격 가까이에 반복 가능한 배지로 제공합니다. MCP·x402·Prisma·외부 카드 ID 같은 내부 용어는 일반 사용자 주 흐름에 노출하지 않습니다.

## Emotion 구현 구조

사용자는 Emotion의 styled-component 방식을 선택했습니다. `@emotion/styled`와 `@emotion/react`를 사용하며 별도 `styled-components` 라이브러리와 혼용하지 않습니다. [Emotion styled](https://emotion.sh/docs/styled), [ThemeProvider](https://emotion.sh/docs/theming)를 기준으로 합니다.

```text
apps/web/src/
  app/
    layout.tsx                   # Server: HTML·메타데이터·Provider 조립
    page.tsx                     # Server: 카드 목록 DTO 조회
    cards/[id]/page.tsx           # Server: 상세·평가·참고 가격 조회
    providers.tsx                # Client: Emotion Registry·ThemeProvider
  styles/
    tokens.ts                    # 색·간격·폰트·반응형의 기본값
    theme.ts                     # 의미별 토큰과 컴포넌트 토큰
    emotion.d.ts                 # Theme 타입 확장
    EmotionRegistry.tsx          # 요청별 SSR cache/flush 검증 후 채택
    GlobalStyles.tsx             # reset·기본 글꼴·포커스
  components/
    ui/                          # Button, Input, Badge, Dialog, Skeleton
    layout/                      # AppShell, Header, Container, EmptyState
  features/
    catalog/                     # CatalogView, SearchForm, CardTile, CardImage
    card-detail/                 # DetailView, CardFacts, ValuationPanel
    market-prices/               # MarketPriceTable, DataSourceBadge
    agents/                      # 후속 API 연결 시 추가
  server/
    api.ts                       # server-only: Core API URL·조회·Zod 검증
  lib/
    formatters.ts                # 순수 통화·날짜·표시 이름 변환
```

페이지는 서버에서 DTO를 받아 클라이언트 표현 컴포넌트로 전달합니다. Emotion을 사용하는 styled 모듈은 Client 경계 안에 둡니다. Client Provider로 감쌌다고 그 아래 서버 데이터 조회 코드까지 브라우저로 옮기지 않습니다. Core API 비밀값은 server-only 모듈에 둡니다. 카탈로그 전체를 클라이언트에서 다시 fetch하는 구조로 바꾸지 않습니다.

작은 컴포넌트는 같은 파일에 styled 정의를 두고, 화면 단위에서 커지면 `Component.styles.ts`로 분리해 `S.Root` 형태로 사용합니다. 스타일 전용 props는 `shouldForwardProp`로 DOM 전달을 차단합니다. styled-components의 `$prop` 자동 필터링 동작을 Emotion에 가정하지 않습니다. 컴포넌트 안의 임의 hex 값과 페이지별 중복 theme 선언을 피합니다.

## 구현 전 기술 확인과 순서

현재 Next.js 16.4.6의 로컬 문서와 [공식 CSS-in-JS 가이드](https://nextjs.org/docs/app/guides/css-in-js)는 Emotion의 App Router 지원을 진행 중으로 안내합니다. Emotion의 [SSR 문서](https://emotion.sh/docs/ssr)는 기본 방식과 스트리밍을 지원하지 않는 고급 extraction 방식을 구분합니다. Pages Router의 `_document` 예제를 그대로 옮기지 않습니다.

1. **Emotion 적용 검증:** 두 경로에 최소 styled 컴포넌트를 적용해 SSR·새로고침·클라이언트 이동·스트리밍 시 스타일 순서, FOUC, hydration 경고를 확인합니다. cache는 서버 요청 간 공유하지 않으며 Registry flush는 실제 검증 후 확정합니다. 이 설계는 호환성 검증 완료 선언이 아닙니다.
2. **공통 기반:** tokens·Theme 타입·GlobalStyles·AppShell·Button/Input/Badge를 구현합니다. 서버 페이지의 데이터 조회를 유지합니다.
3. **카드 탐색:** 실제 이미지, 한국어명, 메타데이터, 검색·빈 결과·로딩·이미지 실패 상태를 적용합니다. 목록 평가 요청 한 건이 실패해도 전체 카드 목록을 오류 화면으로 바꾸지 않도록 개별 실패를 분리합니다. 현재의 카드별 평가 요청 수를 측정하고 필요하면 별도 API 개선을 계획합니다.
4. **카드 상세:** 이미지·속성·데모/시장 평가·원본 참고 시세를 일관된 컴포넌트로 정리합니다. 데이터 모드에 따라 가격 제목을 바꾸고 현재 목록의 고정 Mock 제목을 제거합니다.
5. **검색 기능 확장:** API 계약과 함께 세트·언어 필터, 전체 결과 수와 페이지 이동을 연결합니다. 디자인만으로 지원하지 않는 API 기능을 가정하지 않습니다.
6. **후속 모듈 연결:** 같은 토큰과 레이아웃으로 매물·보유 카드·Agent 작업대·거래 내역을 추가합니다. 거래·결제 정책은 해당 backend 모듈이 소유합니다.

구현 검증은 360/768/1024/1440px, 키보드 탐색, 확대 200%, 이미지·가격 요청 실패, Mock/시장/자료 부족 상태, 실제 브라우저 hydration·FOUC, typecheck·테스트·production build를 포함합니다. 이번 설계 단계에서는 실행 앱·백엔드 계약을 변경하지 않습니다.
